## 一、这个库想解决什么

法条原文在网上都能查到。查不到的，是下面这几个问题：

- 这条法**什么时候**是这个写法，改过没有
- 这条法**要求谁**做什么，义务落在谁头上
- 中国、欧盟、美国在**同一个议题**上分别怎么处置
- 境外对华的措施和中国反制的措施，各是什么、依据在哪

前两个问题，`lexifina/global-law`（Git for Global Law）已经做了一半：它把世界各国的法条做成 git 仓库，一次生效一次提交，于是可以问「某国某天的某条原文是什么」。后两个问题，它结构上做不了——它的 schema 里没有「义务」，也没有「议题」。

**所以本库不和它比收了多少个法域。本库做的是：在中国涉外法治与 AI 治理这一个纵切面上，做到可点时间、可溯源、可比较、可判定。**

## 二、四层结构

| 层 | 内容 | 谁写的 |
|---|---|---|
| **L1 法源** | 法规、文号、发布机关、施行日期、条文 | 脚本从快照切出，逐字核对 |
| **L2 义务** | 一条条文里切出的**原句** + 型态（应当/不得）+ 类别（安全评估/认证/告知同意……）+ 主体 | 原句由脚本核对，类别与概括由编者写 |
| **L3 议题** | 同一问题下各法域的条文与案例并排；每栏声明材料性质，整个议题声明是否可比 | 编者写，链接由脚本核对 |
| **L4 对外措施** | 境外对华措施 / 中国对外措施，两个方向分开记，不合表 | 措施标题由脚本核对，类型与方向由编者分类。已收 18 条 |

### L2 为什么值钱

法条原文可以 grep，但问不出「哪些情形必须申报」「罚则上限多少」「哪几条有域外效力」。

义务层把条文切成一句一句的 operative sentence。**关键不变量：**

```
义务的原句  ⊆  它所指条文的正文  ⊆  该条文的快照
```

原句必须逐字出现在条文正文里，而条文正文早已与快照逐字比对过。所以义务不可能比它读的那条法更可靠。概括（「义务」一栏）是编者写的，和原句**并排显示**，读者一眼能看出概括有没有走样。

### L3 为什么值钱

跨法域对比表最常见的错，是把中国的**部门规章**和美国的**一审判决**并排放，然后说「美国允许、中国禁止」。两者根本不是同一性质的材料，结论不可比。

所以本库的每个争点必须回答两件事：

- 每一栏的材料性质（规范性文件 / 司法解释 / 个案裁判 / 监管指南 / 标准 / 二手材料 / 库内无材料）
- 整个争点**是否可比**；不可比时，必须写明理由

例如新收的争点《个人信息出境的合法路径与门槛》：中国一栏是三部规章，欧盟和美国两栏**如实留白**，并声明「本条不构成三法域比较」。

**七个争点全部填了这两个字段，结论是七个都不可比。** 原因分两类，库里逐条写明：

- **覆盖缺口**：某一法域没有材料（如标识争点的美国、提供者责任争点的欧美）
- **材料性质不同**：中欧是规范性文件、美国是个案裁判；或者三栏规制对象根本不重叠（如人格权争点里，中国是救济、欧盟是透明度、美国限于私密影像）

这不是为了保守。把「中国有规章、美国有判决、欧盟没材料」并排成一张表，读者会自然读成三国对同一问题给出了不同答案——而实际上三类材料回答的不是同一个问题。**声明不可比，是这张表唯一诚实的用法。**

## 三、现在库里有什么

| 项 | 数量 | 说明 |
|---|---|---|
| 法规 | 24 部 | 中国 18、欧盟 3、美国 3；18 部全文入库，5 部只收被判决书援引的条文，1 部只登记元数据 |
| 条文 | 545 条 | 每条的条号和正文一起与快照逐字比对 |
| **义务** | **86 条** | 中国 58、欧盟 21、美国 7；「应当」69、「不得」15、「可以」2；标注域外效力 19 条；均记罚则或制度说明 |
| **对外措施** | **18 条** | 境外对华 11 条（美 8、欧 3）、中国对外 7 条；实体清单、出口管制、关税、投资审查、制裁、阻断、进口禁令七类都有数据 |
| 案例 | 17 件 | 中国 10、欧盟 4、美国 3 |
| 案例—条文关联 | 81 处 | 64 处是判决书明文援引，17 处是编者对应；17 件案例都至少挂了一条条文 |
| 争点 | 8 个 | 含 6 个 AI 治理争点、1 个涉外数据争点、1 个反制裁与反胁迫争点 |
| 待核线索 | 18 条 | 只见于二手材料、还没取到原文，不计入上面的数字 |
| 来源快照 | 78 份 | 61 份取自发布机关自己的页面或文书 |

涉外标记（编者分类）：涉外专门法 10 部、含涉外或域外条款 3 部、无涉外条款 11 部。

**对外措施里最值得看的一条：** 2026 年 5 月 2 日商务部公告 2026 年第 21 号，是《阻断办法》2021 年施行以来的**第一个阻断禁令**——针对美国以涉伊朗石油为由对恒力石化（大连）炼化等 5 家企业采取的 SDN 列名与冻结措施，规定「不得承认、不得执行、不得遵守」。它与美国 2026 年 4 月的 OFAC 行动在库里并排可查，一个方向一条，不合表。

**进口禁令这一层：** 收了 UFLPA 的两条支线——**可反驳推定**（2022-06-21 起，凡原产于新疆或由清单实体生产的货物一律推定为强迫劳动产品，进口商须自证清白）与**实体清单**（2026-10-29 同日列入的华大基因、华大智造、深圳华大科技）。两者不是两项独立制裁，而是同一部法律的执法推定与名单；记录里写明了这层关系，免得被读成两次处罚。另收一条**知识产权授权下的 SDN 认定**（PAIPA，2026-10-19，奇绩创坛及其关联基金）——它与伊朗、俄罗斯等国家紧急状态授权无关，同类制裁很容易被混为一谈。

**美国义务与欧盟案例已补齐：** 美国一侧切出 7 条义务——*TAKE IT DOWN Act* 5 条（第 2 条禁止发布未经同意的成年人/未成年人深度伪造私密影像及刑事罚则；第 3 条平台 1 年内建立通知删除程序、显著公示、收到有效请求后 48 小时内删除及 FTC 执法，均挂入「深度伪造」争点）与 *EO 14179* 2 条（联邦行政系统内部 180 日行动计划与审查撤销 EO 14110 举措，注明不创设可诉权利）。欧盟一侧补入 4 件 AI 治理案例，填补「欧盟 0 案例」缺口：德国汉堡州法院与汉堡高等州法院 **Kneschke 诉 LAION** 一二审（310 O 227/23、5 U 104/24，AI 训练数据与 TDM 例外，挂入训练数据著作权争点）；意大利数据保护局对 **DeepSeek** 下达的停止处理令完整双语决定书（第 33 号决定，2025-01-30，直接涉及 GDPR 域外管辖与中国大模型企业）；意大利数据保护局处罚 **Replika（Luka Inc.）** 500 万欧元案（2025-04-10，可与中国 AI 陪伴案对照）；以及 **OpenAI（ChatGPT）** 案（第 755 号 1500 万欧元罚单及 2026-03-18 罗马法院第 4153/2026 号判决支持上诉的官网最新标注）。

**欧盟义务已切出 21 条：** *EU AI Act* 16 条（覆盖第 5 条禁止实践、第 9/10/12/14/22/26/49/73 条高风险系统与第三国授权代表、第 50 条透明度与深度伪造标记、第 53/54/55 条通用目的 AI 模型版权政策与训练摘要）与**反胁迫工具（ACI）** 5 条（第 5/6/8/11/15 条的认定提案、磋商前置、回应措施、比例上限与保密义务）。AI Act 每一条都在编者注里对照了 *Regulation (EU) 2026/1744* 的修改与延期（如高风险适用日延至 2027-12-02 / 2028-08-02、第 50 条第 2 款旧系统过渡期至 2026-12-02、第 4 条因被整体替换未切）；查询接口返回 AI Act 义务时也会自动附带「已被修订」警示。「训练数据著作权」「深度伪造」「内容标识」「反制裁与反胁迫」四个争点的欧盟一栏均已挂上对应义务。

**AI 治理三部规章切出了义务：** 算法推荐规定 10 条、深度合成规定 7 条、标识办法 7 条，共 24 条。每条都写了罚则出处：算法推荐规定第三十一条对第七、八、九（一）、十六、十七、二十四条等设了警告、通报批评直至一万元以上十万元以下罚款，其余条款按第三十二条转致其他法律；深度合成规定与标识办法都不自设罚则（分别见第二十二条、第十三条）。标识这条线现在是三层：深度合成规定第十六、十七条定义务，标识办法第四、五条细化显式与隐式标识，第六条把核验义务压到传播平台，第十条第一款要求用户主动声明——「内容标识」争点的中国一栏已挂上这 9 条义务。

**新争点：对外国单边制裁与经济胁迫的法律回应。** 中国一栏把对外关系法第三十三条、反外国制裁法、阻断办法三层授权放在一起，并挂上库里已有的反制决定与第一个阻断禁令；欧盟一栏是反胁迫工具。这条争点同样标为**不可比**：中国两部法针对外国对华制裁与域外适用，并直接禁止私人执行或遵守外国措施；ACI 针对第三国政府的胁迫，回应是国家间的贸易投资措施，不约束私人。与阻断办法真正对应的是欧盟 1996 年《阻断条例》，它没有入库，编者注里写明了这一点。

**美国三件案例挂上了条文：** 从 govinfo 取了《美国法典》第 17 编 §102、§106、§107、§201（2023 年版编纂文本），Thaler、Ross、Bartz 三案共 5 处锚点，每处的引文都是法院意见里写出「17 U.S.C. §」和节号的原句。至此 13 件案例全部至少有一条判决书援引或编者对应的条文。

**欧盟的反胁迫工具也收了：** *Regulation (EU) 2023/2675*（ACI），20 条全文，2023-12-27 生效。它是欧盟对第三国经济胁迫的应对框架，与中国的反外国制裁法、阻断办法构成同一问题的三种制度安排。条文本身不点名任何国家，也还没有在任何个案中被启用，所以只进法规层，不进对外措施层——把它记成一条「对华措施」会是编者的臆断。

**欧盟一侧：** 收了欧盟委员会对中国纯电动乘用车的反补贴税终裁（*Implementing Regulation (EU) 2024/2754*，税率 7.8%–35.3%，2024-10-30 起适用）。EUR-Lex 对本次取数全线返回 202，条例原文未取到，所引是委员会新闻稿与其 Access2Markets 通知——记录里写明了这一点，读者不会误以为引的是条例本身。

另补两条：**第 19 轮对俄制裁包中列名的 12 家中国（含香港）实体**（制裁，2025-10-23），以及**对中国移动式高空作业平台的反补贴与反倾销措施**（关税，2025-04-28）。这两条都只有公布日、没有可引用的生效日期——委员会页面用「On Friday」这类相对说法，或只写「在《官方公报》公布之日生效」这条规则。所以它们标「已公布」而不是「现行」，编者注里写明了原因。

**涉外基干法已入库 5 部：** 反外国制裁法（16 条）、出口管制法（49 条）、**两用物项出口管制条例（50 条）**、阻断办法（16 条）、不可靠实体清单规定（14 条）。两条不可靠实体清单措施已挂到授权它的《不可靠实体清单规定》上。

**补上了《对外关系法》（2023-07-01 施行）**，45 条全文入库。这是目前中国涉外法治的基础性法律，也是库里原先最显眼的空缺。义务层从中切了 4 条：第二十九条的国家立法职责、第三十三条第二款的反制制度建设义务、第三十五条第三款的遵守与不得违反两项。第三十三条第一款给的是「有权采取相应反制和限制措施」这项权力，第三款把据此作出的决定定为最终决定——权利与义务分开记，不合并成一条。

出口管制这条线现在是**母法 + 实施条例**两层：2020 年的出口管制法给制度框架，2024 年的两用物项条例给清单、许可、最终用户管理与管控名单的具体规则——实务中援引的几乎都是后者。

以上数字由 `tools/build.py` 从数据文件清点得出，页面「口径」页显示的是同一组数。

## 四、对标 Git for Global Law

`lexifina/global-law`（2026-10-28 建库，2122 star，716 MB）把世界各国的法条做成 git 子模块，一次生效一次提交。manifest 里 991 个语料库，但深浅差距很大：捷克、西班牙、瑞士是整部法典，美国只有 9 编 USC，英国只有特殊教育法一部。

**它对中国法的收录是：1 个语料库、173 部全国人大及其常委会制定的法律，起点 1982-12-04。没有行政法规、部门规章、规范性文件、司法解释、国家标准、裁判文书，也没有任何 AI 专门规范。**

所以涉外法治最要紧的那批东西——网信办的数据出境三部规章、商务部的反制规章、两高涉外司法解释、TC260 国标——它一部都没有。

| 维度 | global-law | 本库 v1 |
|---|---|---|
| 法域数 | 991 个语料库 | 3 个法域，不做广度 |
| 中国法 | 173 部人大层级法律 | 法律 + 部门规章 + 司法解释，含涉外专门法 7 部 |
| AI 治理 | 无专门层 | 法源 + 义务 + 案例 + 议题 |
| 时间性 | 一法一 commit，`In-force` trailer | 施行日期 + 修订关系（逐条版本变动未做） |
| 溯源 | 引用回官方页面 | 引文 SHA-256 快照 + 证据等级 A/B/C |
| 义务结构化 | 无 | 有，17 条 |
| 跨法域比较 | 无（按法域组织） | 议题层，按议题并列，声明可比性 |
| 中文 | 无中文界面 | 原生中文 |
| 接口 | MCP + REST | 静态单页 + MCP（10 个只读工具，零依赖） |

**本库不如它的地方，也说清楚：** 法域数差得远；它做到了一法一 commit 的逐条版本史，本库只到「这部法被哪部法修订过」，没有逐条变动标注；它另有免密钥 REST API 和托管的公共服务，本库只有本地 MCP，需要 clone 下来跑。

## 五、核验规则

**一条规矩：凡是陈述法律或案件事实的字段，必须指向一份本地快照里的逐字原文。对不上，构建失败。**

### 脚本核对的

| 字段 | 要求 |
|---|---|
| 条文 | 条号、标题、正文连在一起出现在快照里（防止张冠李戴）；标「全文」的，条号须从 1 连续到末条 |
| **义务的原句** | 必须逐字出现在它所指向的条文正文里；指错条、改写、总结，都会被拒 |
| 法规标题、文号、发布机关 | 各自在快照中有出处 |
| 法规的发布日、施行日 | **每个日期用它自己的那句原文**核对，不能借另一个日期的句子 |
| 推算出来的日期 | 须写明规则（从哪个日期起、加几天、规则的原文出处），脚本重新算一遍；页面标「推算」。支持「公布后第 N 日」和「自公布之日起施行」两种规则 |
| 「现行」状态 | 必须有已经过去的施行日期 |
| 案例摘录 | 典型案例稿由脚本整段取出，不经手打；判决书的选段与快照逐字一致 |
| 审理机关、案号、裁判日期、各审级的法院和日期 | 各自带出处，且出处里必须出现该法院名、该案号、该日期 |
| 「来源明文援引」的条文关联 | 引文里必须同时出现法规名和条号 |
| 争点里引用的条文、案例、义务 | 必须真实存在；声明「可比」时不得有空栏；声明「不可比」时必须写理由 |
| 数据文件本身 | 每次校验都按入库说明和快照重新生成一遍，与存盘的记录不一致即失败，所以手改数据文件无效 |

**一页多案的处理：** 法院的典型案例稿一页有好几件案子，而且共用套话。每件案例的所有出处只在它自己那一段里找，不能借用隔壁案件的句子。这一段必须载有本案的案名，否则不算本案的段落；多案页面不允许整页使用。

**比对口径：** 只忽略空白和全角半角差异，标点和用字必须一致。英文还要求引文的首尾落在整词上（否则 lawful 会在 unlawful 里「找到」）。出处太短的不算数（中文至少 8 字）。读快照文本前先核对文件指纹。

### 脚本核对不了、靠编者判断的

- 案例的**结果**和**是否终局**
- 法规的效力层级、类型、**涉外标记**
- 义务的**类别**（安全评估 / 认证 / 告知同意……）和**概括**
- 争点的材料性质、可比性判断、各栏概述

这些都需要老师或法学同学复核。

### 核验等级

由脚本按来源算出，不是人工填的：**已核验**（全部引文与发布机关自己的页面一致）/ **转载核对**（至少一份快照是转载页）/ **待核**（尚无快照）。义务的等级继承它所在的法规，不单独填写。

### 这套规则是怎么来的

校验规则经过两轮独立代码审查，**两轮结论都是不通过**，之后又做过一次小范围审查。每一种被构造出来的「事实没有依据却能通过校验」的情形，都有回归测试（`tests/`，共 241 项）。**尚未做完整的第三轮审查**，所以不能说校验已经没有漏洞。

## 六、已知缺口

| 缺口 | 影响 | 怎么补 |
|---|---|---|
| 欧盟措施 3 条里有 2 条只有公布日、没有生效日 | 欧盟外资审查条例未收；ACI 已入法规层但从未启用，无法入措施层；SDN、UFLPA 等名单只收了少数个案，不是名单本身；这两条欧盟措施在页面上标「已公布」而非「现行」 | 换能给出生效日的官方源后改标；名单全量导出需另建数据层 |
| 义务覆盖 17 部法规（中国 13、欧盟 2、美国 2）；民法典、著作权法、个人信息保护法、最高法意见、美国版权法等 6 部尚未切出义务 | 三法域都已有义务，但一般民事/版权法尚未切出义务 | 按议题优先级补中国个保法与民法典核心条文 |
| 涉外标记是编者分类，脚本不核对 | 可能判错 | 请老师复核 |
| 中国还有 1 件案例没有判决书，1 件缺二审判决书 | 仍只有编者关联 | 到裁判文书网按案号查 |
| 中国 9 件案例的裁判文书都不是法院原件 | 6 份取自北大法宝、2 份取自威科先行；快照只在本地留存，不随库分发，别人拿到本库后这几件无法重跑校验 | 从裁判文书网取原件替换 |
| 民法典仍取自中国网信网转载的新华社稿 | 这一部是「转载核对」；著作权法、个人信息保护法已换成中国人大网发布页，是「已核验」 | 人大网只以《常委会公报》PDF 发布民法典，其文字层逐词断行、正文中夹着页码，条文无法作为连续原文入库；需要为公报 PDF 写一个去页码、合并断行的预处理，并让核对规则承认这一步 |
| 欧盟《人工智能法》是 2024 年原始文本 | 2026/1744 号条例的逐条修改没有标注 | 为修订性条例写专门的拆分器 |

| 标「现行」的只依据原文所载施行日期 | 此后是否被修订或废止没有核查 | 定期复核 |
| 条文之间的引用关系没有结构化 | 例如标识办法援引深度合成规定，目前只能靠检索 | 后续版本 |

## 七、给 AI 用：MCP 接口

本库带一个 MCP server，Claude Code、Cursor、Claude Desktop 等客户端可以直接查询。**只用 Python 标准库**，clone 下来就能跑，不用装 SDK。

在 Claude Code 里打开本仓库，`.mcp.json` 会自动登记它（首次会问你是否允许）。其他客户端，或想在别的目录里用：

```bash
claude mcp add aigov-db -- python -I /本仓库的绝对路径/tools/mcp_server.py
```

macOS / Linux 上把 `python` 换成 `python3`。server 读的是 `dist/aigov-db.json`，所以改了数据要先 `python tools/build.py`。

| 工具 | 做什么 |
|---|---|
| `describe_database` | 范围、各层数量、核验等级的含义、没收什么、引用规则。先调这个 |
| `search_law` | 全文检索条文、义务、案例、争点、措施；忽略空格和全半角，不排序 |
| `list_instruments` / `get_instrument` | 法规清单；单部法规的文号、日期（推算的会标出）、条号、义务 |
| `get_provision` | 一条条文的原文、从中切出的义务、援引它的案例、发布机关原址。条号可写 `第七条`、`7`、`第7条`、`Article 50` |
| `find_obligations` | 按类别、型态（应当/不得）、主体、法规、是否域外筛义务 |
| `list_issues` / `get_issue` | 争点；**先返回是否可比**，再返回各栏 |
| `list_countermeasures` | 对外措施，**永远分境外对华、中国对外两个列表返回** |
| `get_case` | 案例的法院、案号、日期、原文摘录、援引的条文 |

每个返回结果都守三条规矩，和网页上一样：

1. **原文与编者判断分开。** `text`、`quote` 是与快照逐字核过的原文；`editorial` 下的类别、概括、案件结果是编者判断，脚本没核对。agent 拿到结果，不会把概括当法条引
2. **引用指回发布机关。** 每个答案带 `cite`：官方原址、取回快照的日期、SHA-256；转载页会加警告。本库副本只供核对，不作引用来源
3. **不可比就先说不可比。** `get_issue` 返回的第一个字段就是 `comparison`；没有命中时明说「本库没有收，不说明不存在」

页面上的规矩，接口同样守。另有一条接口特有的：**条号写错宁可拒绝，也不猜。** `get_provision` 只接受 `第七条`、`（七）`、`Article 7`、`Sec. 7`、`§ 7`、纯数字 `7` 这几种写法；`Article 4a`、`Recital 27`、`第十二条第1款`、`§107(a)` 一律拒绝并列出可选条号——把另一条的原文当作所问条文返回，是这类工具最危险的错误。

## 八、怎么用（维护数据）

```bash
python tools/build.py
```

校验全部记录并生成 `dist/index.html` 和 `dist/aigov-db.json`。只校验不生成：`python tools/build.py --check`

跑测试（223 项）：

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -I -m pytest tests/ -q
```

**新增一部法规：**

1. 取快照：`python tools/fetch.py SRC-编号 网址 --publisher 发布机关 --kind OFFICIAL_TEXT --official`（境外站点加 `--proxy`，代理地址放环境变量 `AIGOV_PROXY`）
2. 在 `ingest/instruments/` 写一份说明：快照编号、体例、起止标记、应有条数；文号、发布机关、每个日期各配一句原文
3. `python tools/ingest_instrument.py ingest/instruments/新文件.json`
4. `python tools/build.py`

**新增一条义务：** 在 `data/obligations/` 写一个 JSON。`quote` 必须逐字取自条文正文，`kind`／`modality`／`subject` 取自 `aigov/config.py` 的词表。写完 `python tools/build.py`，引文对不上会直接报错。

**从订阅数据库取判决书：** `VISIBLE=1 node tools/browser.cjs start` 打开独立浏览器窗口（登录和安全验证由人完成），`goto` 到文书页，`save <选择器> 文件` 存下正文，再用 `python tools/register_snapshot.py` 登记。只取裁判文书正文，不取数据库写的裁判要旨。

环境：Python 3.9 以上；取 PDF 判决书需要 `pypdf`，测试需要 `pytest`。

## 十、许可与引用

本库只分发中国法律、法规、规章的正文（属官方文件）与自己撰写的元数据。第三方数据库（北大法宝、威科先行）的页面快照不随库分发。AGORA 数据集为非商业许可，只当线索用，其数据不随本库分发。

本库供研究检索使用，不构成法律意见。引用前请打开原址核对。
